# PS1版ONEのWindowsネイティブ再実装に向けた環境選定

## 目的

ゲームのデータ形式、シナリオ命令、状態管理、描画・音声・入力の動作を解析し、
Windows上の独立したゲームランタイムとして再実装する。
BIOSとエミュレーターは解析・比較検証の道具として扱う。
まずタイトルから最初の文章表示までを解析・再現の対象とする。

## 2026-09-20時点の選定

| 役割 | 構成 | 判断と根拠 |
| --- | --- | --- |
| 正常動作の比較基準 | DuckStation + 未改造SCPH-5500日本版 | ONE Disc 1でタイトル／オープニング到達をユーザー確認済み |
| 主解析環境 | PCSX-Redux + 同じ未改造SCPH-5500 | Lua観測を有効にしてONEの最初の文章まで到達。RAM/VRAM取得も確認し採用 |
| 主解析環境の代替候補 | DuckStation + 同じ公式BIOS + デバッガー/GDB | ゲーム動作確認済み。必要なログ取得・自動化の実用性は別途検証する |
| BIOS内部の理解・実験 | 既存のOpenBIOSフォーク | ソース参照・ログ実験に利用。ONEではCD読み込みエラーが再現するため、基準にはしない |
| 補助的な計測手段 | 公式BIOSの実行時パッチ、または改造コピー | 観測対象と必要性を明らかにしてから限定的に使う。今回は未実装 |

提供BIOSのMD5: `8dd7d5296a650fac7319bce665a6a53c`。
DuckStationのSCPH-5500 (v3.0 09-09-96 J)登録値と一致。
OpenBIOSでのエラーはログ無効ReleaseおよびInterpreterでも再現した。
公式BIOSでは同じDisc 1・設定でCDエラーが出ず描画初期化に進んだ。
全編の互換性を保証する検証ではない。

## 観測対象

1. BIOS呼び出し: A0/B0/C0入口の関数番号、PC、RA、引数、戻り値。
   呼び出し規約やネストを確認し、戻り値の対応付けを行う。
2. CD: コマンド、セクター位置、転送量、DMA転送先。
   ディスクのファイル配置と照合し、ファイル→RAMの対応を作る。
3. ゲーム内部: データ展開、シナリオ命令の解釈、文章描画、選択肢・フラグ更新。
   実行ファイルと必要に応じたRAMダンプを静的解析に渡して関数を対応付ける。
4. 描画・音声: GPUコマンド、VRAM、SPU転送とゲームの高水準処理を対応付ける。

ゲームがハードウェアを直接操作する経路はBIOS呼び出しログに現れない。
また、BIOS呼び出し履歴だけからゲーム内部のシナリオ仕様は確定できない。
そのためCPU・メモリー・デバイス側の計測を組み合わせる。

## 公式BIOS改造の扱い

未改造版を基準として保持し、最初にエミュレーター側のフックでBIOS入口・出口を観測する。
内部状態の取得に追加コードが必要なら、対象ハッシュを固定した実行時パッチまたは
改造コピーを用意する。元ファイルを上書きしない。
パッチ位置・元バイト列・置換内容・意図を記録する。

パッチではレジスター、スタック、分岐遅延スロット、キャッシュ、割り込み中の
再入可能性を確認する。割り込み・CD処理内で大量の文字出力を行うと、
調べたいゲームのタイミングを変える可能性がある。
可能ならエミュレーター側で記録し、フィルターをかけたイベントを外部へ保存する。
同じ入力・場面で未改造版と比較して計測による動作差を確認する。

## 採用前の実験

1. PCSX-Reduxで公式BIOSとONE Disc 1を起動。タイトルと最初の文章表示を確認。
2. Interpreterとデバッガーを有効にして同じ場面に到達できるか確認。
3. BIOS呼び出しと特定メモリー範囲の読み書きをLuaで記録。
4. RAM/VRAMを外部取得し、選択した場面・入力・ディスク/BIOSハッシュと紐付ける。
5. メモリー破損、CD再試行、ログによる大幅な遅延がないか、計測なしと比較。

PCSX-Reduxでゲーム動作や必要な観測が成立しなければ、DuckStationを主解析に採用する。
Luaブレークポイントの公式ドキュメントはInterpreterとデバッガー有効を前提としている。
全命令トレースを常時保存するのではなく、対象の場面・アドレス範囲・イベントに絞る。

## 初回検証結果（2026-09-20）

PCSX-Redux `25477.20260919.11.x64` + 未改造SCPH-5500で採用前実験を実施。
Interpreterでオープニング、タイトル、最初の文章表示まで到達した。
BIOS入口のLua観測を有効にしても到達でき、RAM・VRAM・画面の外部取得に成功。
観測なし／ありのロード選択画面では画面とVRAMのハッシュが一致した。
主解析環境としてこの構成を採用する。DuckStationは引き続き比較基準にする。

[取得ツールと再現手順](../tools/one-analysis/README.ja.md)を参照。
日本語ディスクパスは文字コード変換エラーになるため、英数字の作業用コピーを使用。
公式BIOSのパッチとWindowsランタイム実装はまだ行っていない。
続く解析では冒頭シナリオの圧縮資源を特定し、PC側の展開結果36,619バイトが
ゲームのRAMと完全一致した。命令処理の確認範囲は
[シナリオ解析メモ](one-scenario-findings.ja.md)に記録した。
