# 本編シナリオの収集範囲の再確認

2026-09-20。ユーザーの指定により本編のDisc 1 / SLPS-01972のみを対象とする。
Disc 2は本編ではないため収集対象外。統合ファイルの作成よりも収集範囲の確認を優先した。

## 結果

既知の名前付き表85行について、欠落なく再抽出し、従来のハッシュと一致した。
重複を除いた84実体はLBA 1776〜2204に、読込みセクター数に基づく配置として
隙間なく並んでいる。表の一部の名前だけを抜き出した状態ではない。

名前表0x80061F98は添字84のNAEまで文字列ポインターで、直後の添字85相当位置には
ポインターではなくASCIIの `NOTHING` がある。
位置表0x8005DD88はその先にも読込み位置らしい値が続くが、名前表の続きとは
対応しないため、これだけで追加シナリオとは扱わない。

## DATA.BIN内の追加候補の探索

DATA.BIN 28,233,728バイト全体の2048バイト境界を調べた。
既知の圧縮形式として扱える長さヘッダー657件を試し、655件を展開できた。
ただしランダムなデータでも展開できる場合があるため、655件は資源数ではない。
圧縮サイズ・展開サイズとも262,144バイトを上限とし、展開上限に達した2件は除外。
他の13,129境界はヘッダー条件を満たさなかった。

展開結果に `10 + CP932文章 + 81 66 + 00/01` という形が3か所以上あるものを
追加の文章候補として保全した。これは命令境界を証明する判定ではない。
既知表にない候補は1件（DATA.BIN内0x1B0000）だったが、調べると以下の関係だった。

- DS03の圧縮データ先頭: 0x1AC800。
- DS03の圧縮データ終端（含まない）: 0x1B1578。
- 候補0x1B0000はその内部。

したがってこれは独立したファイル先頭として採用しない。
再分類した結果、この探索条件で新しい独立シナリオ候補は0件。
元データと判定経緯は残し、候補を消して発見がなかったようには扱わない。

## 別の読み込み経路

シナリオRAMへの別経路として、0x80017D4Cを呼ぶ処理がある。
呼び出し元の文字列テンプレートは `sim:%s`。
0x80017D4Cはopen相当処理・read相当処理・seek相当処理でファイルを読み、
呼び出し元が渡したRAMへ置く。CDの位置表を使う圧縮展開経路とは異なる。

この経路の存在は、Disc 1上に追加のISOファイルがあることの証明ではない。
ホスト側ファイル等の開発用経路の可能性があるが、接続先・利用条件は未確定。
未知の素材や元スクリプトが収集済みとは主張しない。

## 収集と解読の区別

**既知の名前付きシナリオは収集済み。一方、その中の命令解読は途中。**
前回の約7.36%という値は命令境界をたどれたバイト範囲であり、シナリオファイルを
7.36%しか収集できていないという意味ではない。

今回の再確認で「足りない本編シナリオファイル」は新たに特定されなかった。
未整列データ、別圧縮方式、上限超え資源、短い文章を持つ資源、文章のないスクリプト、
音声・動画領域等はこの探索だけでは排除できない。絶対的な全件保証とはしない。
