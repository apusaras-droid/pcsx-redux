展開結果およびRAM対象領域のSHA256:
`0e007ed063b368fc522fe1a8a6915e38e2335b5d8f04510ffe91f6e33f7839fa`

## 圧縮形式

先頭のリトルエンディアン32ビット整数がヘッダーを含む圧縮サイズ。
その後はLZSS形式で、フラグを下位ビットから8個ずつ処理する。
1ならリテラル1バイト、0なら2バイトの辞書参照。
辞書位置は `low | ((high & 0xF0) << 4)`、長さは `(high & 0x0F) + 3`。
4096バイトのリング辞書で、初期書き込み位置は0xFEE。
重複する参照は1バイトずつコピーする。

元の関数がゼロ初期化するのは辞書の先頭4078バイトのみ。
今回のデコーダーは残り18バイトへの未初期化参照をエラーにする。
サイズ境界で未完のフラグ群・参照に達すると、それまでの結果を返す挙動は元の関数に合わせた。
全資源に適用可能であるとはまだ確認していない。

## シナリオ処理の確認範囲

| 場所 | 観測・静的解析の結果 |
| --- | --- |
| 0x80018480 | シナリオ処理関数の先頭 |
| 0x80018528 | シナリオバイトの読出し。RAM監視で実行を確認 |
| 0x800100C4 | 命令分岐テーブル。直前に0x9A未満かを検査 |
| gp + 0x978 | シナリオ内の現在位置を保持するワード（静的解析） |
| 命令0x10 → 0x8001876C | 文章処理への分岐（静的解析） |
| 0x800189B8 / 0x80018D64 | 文章バイトの読出し。RAM監視で実行を確認 |
| 0x800FD088 | 文章用バッファー。冒頭の文章を確認 |

冒頭の命令0x10は資源内+6、最初の文章は+7から始まる。
文章のバイト列はCP932で読める。文章処理には0x81 0x66の組を検査する分岐がある。
ただし、この組を全データから検索するだけでシナリオを解釈することはできない。
0x16等の後続命令の完全な意味、分岐・フラグ・既読・選択肢は未確定。

## 再現と次の検証

[ツールの手順](../tools/one-analysis/README.ja.md)を参照。
ローカル成果物は `.tools/redux-analysis/scenario/` に保存:

- `verified-opening/verification.json`: 以前の冒頭RAMとの照合。
- `verified-reload/verification.json`: リセット後のRAMとの照合。
- `scenario-reads.csv`: 一文目から二文目へ進めた際の読出し。
- `scenario-writes.csv`: リセットからロードした際の書き込み。
- `text-engine.asm`, `executable.asm`: ローカル解析用逆アセンブル。

次は命令境界を守った小さな解釈器を作り、未知の命令では停止させる。
エミュレーターのシナリオ位置・文章バッファーと一操作ずつ比較して、
文章送りと待機の仕様を確認する。Windowsランタイムはまだ未実装。
