# シナリオにスクリプトが含まれる根拠

2026-09-20、ONE Disc 1 / SLPS-01972を調査。
結論: 展開したシナリオ資源は文章だけではなく、専用の命令列を含む。
実行ファイルには命令バイトを読み、分岐表で処理を選ぶ解釈器がある。
開発時のソース言語・ツール名や、テキスト形式の元スクリプトは未確認。

## INITの解読

17バイトのINITは、確認済みの命令境界に従うと以下になる。
以下の変数名は説明用であり、開発者が付けた名前ではない。

| オフセット | バイト | 解読 |
| --- | --- | --- |
| 0x00 | 60 0A 01 | byte_vars[10] = 1 |
| 0x03 | 60 06 0A | byte_vars[6] = 10 |
| 0x06 | 60 0C 0A | byte_vars[12] = 10 |
| 0x09 | 60 0D 0A | byte_vars[13] = 10 |
| 0x0C | 60 0E 0A | byte_vars[14] = 10 |
| 0x0F | 5F 3F | 条件付きの実行経路で資源63（NV30）をロード |

命令0x60の処理先0x8001AC6Cは、次のバイトを添字、その次を値として
`0x800FA840 + 添字`へ1バイト書き込み、シナリオ位置を3進める。
以前取得した冒頭RAMでも上記5変数すべてが一致した。
値一致だけで全実行経路を証明するものではないが、コードの解読を裏付ける。
これらの値が好感度・表示設定などの何を表すかは未確認。

隣接する命令0x61と0x62は同じ領域への加算・減算で、最後に1バイトを書き込む。
この2命令は静的解析による確認であり、今回は実行時の変更を追跡していない。
0x5Fには別の条件経路もあるため、無条件のジャンプとは記述しない。

## 冒頭NV30の構造

冒頭を命令としてたどると次の並びになる。

1. `60 00 00`: byte_vars[0] = 0。
2. `80 0D 01`: 3バイトの命令。処理先0x8001AF04、意味は未確定。
3. `10`: 文章処理。続いて冒頭の文章が入る。
4. `81 66 00`: この文章ブロックを終える処理で消費されるバイト列。
5. オフセット0x1Cに命令0x16が続く。

文章処理の分岐先は0x8001876C。
文章末尾を検査する処理は0x80018D64以降にあり、0x81 0x66の後ろが0の
場合はその0も消費して戻る。その他の末尾・文章内制御はまだ一般化していない。
過去のRAM読出し監視でも、冒頭文章の次に0x800EA744（資源内0x1C）を
命令読出し位置0x80018528から読むことを確認している。
0x16の完全な待機条件・入力仕様は未確定。

つまり、シナリオ本文と制御命令が同じ資源内に混在する形式である。
すべての文章に別ファイルのスクリプトが添付されている、という意味ではない。

## 再現用の限定的な解析器

`tools/one-analysis/inspect_script.py`を追加した。
既知の0x60〜0x62、長さのみ確認した0x80、0x5F、冒頭の0x10を読み取る。
未知命令、資源の移行、最初の文章で停止する。ゲームの実行や全編の抽出はしない。

```powershell
python tools/one-analysis/inspect_script.py .tools/redux-analysis/scenario/init.bin .tools/redux-analysis/new-init-instructions.json
python tools/one-analysis/inspect_script.py .tools/redux-analysis/scenario/verified-opening/scenario.bin .tools/redux-analysis/new-opening-instructions.json
```

ローカルの検証結果:

- `init-instructions.json`: 6命令を確認、資源移行で停止。
- `opening-instructions.json`: 3命令を確認、最初の文章で停止。
- `init-ram-check.json`: 5つの代入値と冒頭RAMの一致。

いずれも `.tools/redux-analysis/scenario/` に保存。
